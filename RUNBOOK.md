# Alfred Runbook — How to Use and Manage

## What Alfred actually is
A personal memory system. Everything you work on and learn gets captured here, indexed, and made queryable in plain English. You query it via Claude Code's MCP tools or the HTTP API.

---

## Daily flow (what happens automatically)

| What | When | Trigger |
|---|---|---|
| Session captured to inbox | On session end | Hook in `~/.config/claude/hooks/session-end.sh` |
| Curator processes inbox | Every 10 seconds | Alfred daemon |
| Janitor reviews vault files | Every 4 hours | Alfred daemon |
| Distiller extracts learnings | Nightly at 2am | Alfred daemon (scheduled) |
| Consolidator writes synthesis | Every 30 min | Alfred daemon |
| Surveyor re-embeds changed files | Every 60 seconds | Alfred daemon |

**You don't need to do anything for sessions to be captured.** Just close Claude Code normally.

## Service management

```bash
# Status of all 5 vaults
systemctl --user status alfred alfred-neuroscience alfred-finance alfred-personal alfred-content
```

## Querying Alfred (in Claude Code)

The MCP tools are loaded automatically. Just use them in any Claude Code session:

```
vault_query "what did I learn about agent architecture last week"
vault_search "tribe social TRIBE v2"
vault_read_record "sessions/my-session.md"
vault_entity_lookup "EMM"
vault_status          ← how many files are indexed
vault_api_cost        ← today's API spend
```

For the HTTP API (from terminal or scripts):
```bash
curl -s http://localhost:8765/query -H 'Content-Type: application/json' \
  -d '{"query": "what did I learn about content creation"}' | jq .
```

## Content creation workflow

**Vault location:** `/mnt/external/vault-content/`

**Folder structure:**
- `inbox/` → drop raw ideas here; Curator picks them up automatically
- `ideas/` → fleshed-out ideas (who/what/why/hook)
- `drafts/` → scripts, posts, threads in progress
- `published/` → archived after going live (ignored by indexer)
- `hooks/` → reusable opening lines and patterns
- `templates/` → platform-specific formats (Reels script, thread, carousel)
- `analytics/` → engagement data, what worked and why
- `briefs/` → research briefs generated by querying other vaults

**Content brief pipeline:**
1. Have a session idea → ask Alfred: `vault_query "everything I know about [topic]"`
2. Combine context into a brief → drop brief into `vault-content/briefs/`
3. Write draft in `vault-content/drafts/`
4. After publishing, move to `published/` and log metrics in `analytics/`
5. Distiller runs nightly → extracts reusable angles/hooks from what performed well

**Querying across all vaults for content research:**
```
# In Claude Code (uses meta server across all 4 main vaults)
vault_query "what do I know about dopamine and decision making"
vault_query "tribe social reels performance findings"
```

## Giving Alfred feedback on results

If a retrieved result was useful or useless, tell Alfred so future queries improve:

```
vault_feedback path="sessions/my-session.md" signal=1    ← helpful
vault_feedback path="sessions/bad-result.md" signal=-1   ← not helpful
```

## If things break

```bash
# Check if all services are running
systemctl --user is-active alfred alfred-neuroscience alfred-finance alfred-personal alfred-content

# Service stuck? Check the log for errors
tail -50 /home/rippere/alfred-v2/data/alfred.log | grep -i error

# Nuclear restart
systemctl --user restart alfred alfred-neuroscience alfred-finance alfred-personal alfred-content alfred-mcp-http

# Sessions not showing up? Check the inbox
ls -la /mnt/external/obsidian-vault/inbox/
# If files are there, Curator hasn't processed them yet. Check the log.
# If inbox is empty, the session hook isn't firing. Check:
cat ~/.config/claude/settings.json | grep -A5 SessionEnd
```
